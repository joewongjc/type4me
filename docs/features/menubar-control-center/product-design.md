## 1. 背景

Type4Me 的菜单栏入口目前是轻量状态展示和设置导航：顶部显示状态，随后平铺 `appState.availableModes`，点击模式后打开设置并跳转到对应模式，底部提供历史、偏好设置和退出。它更像“模式快捷键速查表”，而不是一个能完成工作的入口。

与此同时，产品已经从语音转文字工具发展为语音输入工作台：包含智能感知、翻译、随便问、Mac 操作、改口、ASR 与 LLM 多引擎、麦克风选择、实时文本、输出格式、词汇和历史等能力。用户在工作中经常需要临时切换麦克风、翻译目标或识别引擎；为此进入 Settings 是不必要的中断。

本设计将菜单栏重新定义为 **Type4Me Runtime Control Center（运行控制中心）**：

- Settings 负责“Type4Me 长期如何工作”：首次配置、凭证、复杂编辑和管理；
- 菜单栏负责“我现在立刻要做什么”：开始、结束、恢复、临时切换和回到刚才的结果。

## 2. 产品目标与非目标

### 2.1 核心目标

1. 不打开 Settings 也能以当前可用模式直接开始口述。
2. 让菜单结构随运行阶段变化，而非始终展示同一份静态快捷键列表。
3. 将高频、低风险的调整放在菜单栏：麦克风、可用 ASR、翻译目标、实时文本和常用输出格式。
4. 在不泄露用户正文、剪贴板或提问内容的前提下，提供复制上一条结果、改口、随便问、词汇和历史入口。
5. 保留快捷键工作流；菜单栏是补充入口，不替代 HotkeyManager 或录音浮动条。

### 2.2 成功标准

- 点击“开始口述 → 任意模式”会直接开始同一轮录音，而不是跳转设置；
- 录音中可从菜单完成或取消，处理中的菜单明确区分本轮上下文和下一轮设置；
- 仅展示已配置且可立即工作的 ASR Provider，未配凭证的 Provider 保持在 Settings；
- 用户能在菜单切换麦克风、翻译目标和实时文本，下一轮行为与 Settings 修改完全一致；
- 没有历史或改口目标时，相应动作不误导用户；菜单从不预览最近口述的正文；
- 更新和权限异常有明确恢复入口；
- 所有一级入口保持可扫描，日常就绪状态原则上不超过 12–16 行，复杂选项进入二级菜单。

### 2.3 非目标

第一版不把以下能力搬入菜单栏：API Key、Base URL、Provider 首次配置和测试；Prompt、模式名称、模式快捷键、短文本阈值编辑；麦克风优先级排序；完整历史筛选/删除；开机启动、Dock、代理、语言和调试设置；模型下载；以及任何口述、选中文本、剪贴板或 Ask Anything 正文预览。

## 3. 设计原则

### 3.1 Action first

菜单优先放“现在执行”，不是“去哪里配置”。例如“翻译目标 → 日语”立即切换目标；“MacBook Pro 麦克风”立即作为下一轮输入；模式项立即开始对应录音。只有复杂管理才提供“管理模式…”或“配置识别引擎…”入口。

### 3.2 高频与低风险优先

是否进入菜单栏由“一天内是否可能切几次”决定，而不是功能是否重要。凭证和 Prompt 很重要，但不应占据运行控制面。

### 3.3 当前可用优先

菜单只展示可立即使用的能力：模式来自 `availableModes`；ASR 来自已配置且 Registry 标示可用的 Provider；本地双引擎只在 local build 且本地 ASR 可用时出现；无改口目标时隐藏改口；无历史时禁用复制；无更新时不留占位。

### 3.4 状态决定菜单

菜单不保留常驻状态卡。就绪与完成状态直接从下一步可执行操作开始；录音时由“完成录音 / 取消录音”表达状态；只在处理或恢复导致菜单暂时无法开始新录音时，以一行紧凑文字加图标说明动态状态。错误以红色提示行呈现，并只在仍需用户关注时显示。模式、引擎和麦克风属于可操作菜单，不在状态区重复展示。

### 3.5 本轮冻结、下轮生效

模式、麦克风、ASR、翻译目标及 LLM 上下文在录音开始时冻结。录音或处理时修改菜单不得隐式改变当前任务；会影响当前任务的项只读或标记“下一轮生效”。实时文本和录音动效等纯 UI 偏好可以即时调整。

### 3.6 隐私最小暴露

菜单可展示模式名、Provider、设备名、目标语言、状态和开关；不得展示转写正文、剪贴板、选中文本、问答内容、API Key 或账户敏感信息。

## 4. 信息架构

菜单由五个稳定区域组成，并按运行状态按需插入一行动态提示：

1. **主要动作区**：开始、完成、取消、改口与撤销；
2. **快捷控制区**：麦克风、ASR、翻译目标、实时文本、输出格式、录音反馈；
3. **工作区入口**：复制上一条、随便问、词汇、历史；
4. **系统事件区**：权限与更新的条件入口；
5. **应用区**：打开 Type4Me 首页、Settings 和退出。

### 4.1 就绪状态

默认结构如下（各项按可用性动态出现）：

```text
开始口述 ▸
改口上一条… / 撤销刚才的改口
────────────────────
麦克风 ▸
识别引擎 ▸
翻译目标 ▸
✓ 实时展示文本
输出格式 ▸
录音反馈 ▸
文本模型 ▸                  （P1；满足条件时）
────────────────────
复制上一条结果
打开随便问…
词汇…
历史记录…
────────────────────
有新版本 vX.Y.Z…            （仅有更新时）
打开 Type4Me                  （固定打开首页）
设置…                         ⌘,
退出 Type4Me                  ⌘Q
```

状态摘要过长时优先保留模式名和麦克风名；Provider 可截断而不显示正文。

### 4.1.1 应用窗口入口

菜单栏提供两个语义明确的应用入口，不以“上次停留的标签页”决定落点：

- **打开 Type4Me**：始终进入“首页”，作为模式与使用概览的稳定起点；
- **设置…（⌘,）**：始终进入“设置”，用于偏好与系统权限。

词汇、历史记录、随便问和管理模式等带有明确目的的菜单项，继续直接打开各自页面。

### 4.2 开始口述

一级菜单只保留“开始口述 ▸”，二级菜单由当前 `availableModes` 动态生成：

```text
开始口述 ▸
  快速模式                         Fn
  智能感知                         Fn⌃ / ⌥1
  翻译模式 → 英语                  Fn⇧ / ⌥2
  随便问                           FnSpace / ⌥3
  Mac 操作                         ⌥4
  语音润色                         ⌥5
  …
  ────────────────
  管理模式…
```

模式点击后关闭菜单并立即开始录音，不打开 Settings。快捷键只作为可扫描提示；多个绑定以 `A / B` 展示，无绑定时不显示“未绑定”。翻译模式必须显示当前目标语言，避免用户开始后才发现目标错误。

### 4.3 录音、处理与恢复

录音阶段（`.preparing` 或 `.recording`）替换主要动作区：

```text
完成录音
取消录音
```

“完成录音 / 取消录音”已经明确表达录制状态，菜单不再重复显示本轮模式、麦克风或翻译目标。此时模式、麦克风、ASR、翻译目标、文本模型和输出格式只读，防止用户误以为会影响本轮。实时文本和录音动效仍可改。

处理或恢复阶段仅显示一行“整理中 / 恢复中”等动态状态，不再重复本轮模式、识别引擎或文本模型摘要；只允许明确标示为“下一轮设置”的切换。第一版不新增取消 LLM 处理，除非底层 Session 先提供可靠取消语义。完成不保留顶部状态；错误沿用浮动条现有自动隐藏规则，并在仍可见时显示红色错误行和恢复入口。

### 4.4 权限与更新

优先显示阻断录音的权限问题，例如“麦克风权限未开启 → 修复权限…”。Accessibility 缺失时也显示统一引导入口。用户从系统设置完成授权并回到 Type4Me 后，菜单必须立即重新读取权限并移除已恢复的告警。更新仅在 `availableUpdates` 非空或下载/安装进行中出现，状态分别为可下载、下载中和安装并重启；无更新不占行。

## 5. 快捷控制

### 5.1 麦克风

菜单提供一次性选择，而不是编辑优先级：

```text
麦克风 ▸
  ✓ 跟随系统（当前：MacBook Pro 麦克风）
  ────────────────
  MacBook Pro 麦克风
  AirPods Pro
  Studio Display 麦克风
  ────────────────
  管理麦克风优先级…
```

选择具体设备时保存为单项优先级并作用于下一轮；设备断开时回退到现有优先级/系统默认策略，菜单显示实际解析结果。连接设备列表变化要刷新菜单。

“跟随系统”不是抽象占位项：菜单通过 CoreAudio 读取当前系统默认**输入**设备，并将其名称显示在该项内。若用户选择了优先设备，菜单另以次级只读行展示 Type4Me 下一轮实际会使用的设备（包括优先设备不可用时的系统输入回退）。这样不会把输出设备、可选设备列表与实际录音设备混为一谈。

实际输入设备改变时（系统默认输入改变、优先设备断开/恢复，或用户改动了设备偏好导致有效设备改变），应用复用现有浮动条的短提示显示“输入设备已切换至…”，不发送 macOS 系统通知。启动时仅建立基线、不提示；录音或处理期间不打断浮动条，待当前会话结束后再显示最新一条设备提示。

### 5.2 识别引擎

仅展示 Registry 中可用且配置完毕的 Provider，以及无凭证可直接使用的 Provider。切换 Provider 后下一轮重新计算可用模式和热键；若当前模式不被新 Provider 支持，显示既有的降级或提示语义。菜单底部“配置识别引擎…”直接进入模型设置页，而不是通用偏好页。

local build 还可在本地识别下显示 SenseVoice 实时预览和 Qwen3 最终校准的受条件控制菜单；pure build 不显示该层。

### 5.3 翻译目标

只在翻译模式存在时提供一级子菜单，复用翻译模式支持的语言列表与持久化：

```text
翻译目标 ▸
  ✓ English
  简体中文
  繁體中文
  日本語
  한국어
  Français
  Español
  …
```

切换即时保存，下一轮开始时冻结；不会改变已经录音或处理中的请求。

### 5.4 实时文本、输出格式与录音反馈

“实时展示文本”是一级 Toggle，直接映射既有 `tf_showLiveTranscript` 偏好。输出格式放入二级菜单，复用当前模式标点覆盖、全局 CJK 间距（盘古之白/保持原样/移除空格）、直角引号和保留剪贴板策略；Ask Anything、Mac Action 等不支持输出格式的模式不显示其模式标点项。

录音反馈是 P1：录音动效、录音时降低系统音量和提示音放入二级菜单。动效可即时变更；音量和提示音默认下一轮生效。麦克风 Keep Alive 不进入第一版。

### 5.5 文本模型

此项为 P1。只有两个以上保存且可立即工作的 LLM 配置，且不存在 Settings 草稿覆盖风险时才展示。菜单不编辑凭证、Base URL 或自定义模型名；若无法安全切换，入口只打开模型设置。

## 6. 动作型入口

### 6.1 改口与撤销

有效改口目标存在时显示“改口上一条…”，直接进入既有改口录音流程。`latestReviseUndoTicketID` 有效时优先显示“撤销刚才的改口”。没有目标时隐藏，不长期灰显。

### 6.2 复制上一条结果

从 HistoryStore 复制最新有效的最终文本。对同一条已完成口述，优先复制最新一条未撤销改口的结果；撤销后依次回退到前一条有效改口或原始最终文本；空、失败或取消记录忽略。菜单不显示文本预览，复制后临时显示“✓ 已复制上一条结果”，不弹系统 Alert。

### 6.3 随便问、词汇和历史

- “打开随便问…”打开现有 Ask Anything 工作区；“开始口述 → 随便问”则新开一轮问题录音；
- “词汇…”第一版打开 Vocabulary；P1 可在用户明确选择文本时增加“添加为热词/创建片段”快捷动作；
- “历史记录…”保留进入 History 的现有语义。

## 7. 可访问性、本地化与变体

菜单使用原生 SwiftUI `Button`、`Toggle` 和 `Menu`，支持 macOS 键盘导航与系统勾选状态；层级最多两级。新增文案全部使用 `L(中文, English)`，包括 Start Dictation、Finish Recording、Cancel Recording、Microphone、Speech Recognition、Translation Target、Live Transcript、Output Formatting、Recording Feedback、Copy Last Result 和 Settings。

pure variant 只显示可用云 ASR 与 Apple Speech；local variant 在本地能力存在时显示 SenseVoice/Qwen3 子项；暂停的 subscription variant 不增加账户菜单。

## 8. 分期与验收

### 8.1 P0

- 按需动态状态提示；
- 模式直接启动；
- 录音完成/取消；
- 麦克风和已配置 ASR 切换；
- 翻译目标、实时文本和输出格式；
- 复制上一条结果；
- 随便问、词汇、历史、权限、更新、Settings、退出；
- 菜单状态与动作路由测试。

### 8.2 P1

- 录音反馈完整子菜单；
- 多 LLM Provider/Model 切换；
- SenseVoice/Qwen3 详细控制；
- 词汇的选中文本快捷动作；
- 更丰富的改口和更新下载进度。

### 8.3 验收场景

1. 菜单以智能感知开始录音，完成后结果注入原目标应用，历史模式正确。
2. 选择日语后启动翻译，输出为日语；录音后改变设置不污染本轮目标。
3. AirPods 连接后切换到 AirPods，下一轮使用该设备；断开后菜单显示实际回退。
4. 已配置 Volcano 与 Soniox 时菜单只展示可用项；切换后可用模式与下一轮历史元数据正确。
5. 完成一次转写后复制上一条，剪贴板得到最终文本而菜单不泄露正文。
6. 撤销麦克风或 Accessibility 权限后出现正确引导，恢复授权后告警消失。
7. 菜单启动录音后按模式热键、按 ESC、跨模式结束，都符合既有热键和 Session 语义。

## 9. P0 实现记录

- 菜单入口已替换为运行控制中心，代码位于 `Sources/Type4Me/UI/MenuBar/MenuBarControlCenter.swift`；它只显示状态、设备名、Provider、语言和可用性，不缓存或预览任何口述正文。
- 录音启动、完成、取消、改口和撤销均委托给 `AppDelegate` 与既有 `RecordingControlCoordinator`/`RecognitionSession`，没有新增独立录音状态机或伪造热键 binding。
- 本期落实 P0；录音反馈、LLM 模型切换及本地双引擎细项仍按 §8.2 留在 P1。

## 9. 产品决策总结

这不是把更多设置塞进菜单栏，而是明确两套 UI 的职责。Settings 服务于长期配置与复杂管理；Menu Bar 服务于即时动作、运行状态、高频切换和恢复入口。用户应能在不离开当前工作上下文的情况下完成：选择模式、开始说、控制录音、临时切设备/引擎/目标语言、取回最近结果并回到工作区。

# Groq Whisper ASR 产品设计

> 文档类型：产品设计
> 文档状态：当前有效（设计完成，待实现）
> 设计日期：2026-10-17
> 最后校验：2026-10-18
> 下游文档：`docs/features/groq-asr/development-design.md`
> 官方文档：https://console.groq.com/docs/speech-to-text

## 1. 背景

Groq 在自研 LPU 上托管 OpenAI 开源的 Whisper 模型，提供兼容 OpenAI 的 `/audio/transcriptions` 接口。它的特点是**极快、极便宜**：

| 模型 | 官方价格 | 速度系数 | 官方 WER | 翻译到英文 |
|---|---:|---:|---:|---|
| `whisper-large-v3-turbo` | $0.04 / 小时 | 216× | 12% | 不支持 |
| `whisper-large-v3` | $0.111 / 小时 | 189× | 10.3% | 支持 |

对比 Type4Me 现有的 OpenAI Provider（`gpt-4o-transcribe` $0.36/小时），Groq Turbo 价格不到其 1/9。速度系数 200× 意味着服务端处理很快：实测从发出请求到拿到结果，5 秒的短句约 2 秒，30 秒的录音约 3.5 秒（含网络往返）。对于“松手即出字”的非实时听写，这是目前性价比最高的选择之一。

用户其实可以把 OpenAI Provider 的 Base URL 改成 `https://api.groq.com/openai/v1`，再手填模型名来使用 Groq，但这样有几个问题：

- 模型选项里是 OpenAI 的模型，填错就会报 404；
- 价格标签是错的；
- 没有中文简体引导、静音幻觉防护和热词映射；
- 很难被用户发现。

因此需要一个一等的 Groq Provider。

## 2. 产品目标

### 2.1 核心目标

1. 在“语音识别引擎”中新增 **Groq**，开箱提供 Whisper Large v3 Turbo 和 Whisper Large v3 两个模型；
2. 默认使用 Turbo，主打低价、低延迟；Large v3 作为准确率优先的选项；
3. 与现有非实时 Provider（OpenAI、MiMo、自定义）体验一致：录音中缓存，松手后一次提交；
4. 中文输出默认为简体，避免 Whisper 常见的繁体或繁简混杂输出；
5. 将 Type4Me 热词映射为 Whisper `prompt`，改善专有名词的拼写；
6. 防止 Whisper 在静音或极短录音上产生幻觉文本（如“谢谢观看”“Thank you.”）；
7. 测试连接必须真正校验 API Key，不允许假成功；
8. 中英文界面文案完整。

### 2.2 成功标准

1. 用户在设置中选择 Groq，填入 `gsk_` 开头的 API Key，点击“测试连接”即可得到真实的成功或失败结果；
2. 设为默认后，按住快捷键说话、松开，文本经现有 Direct / LLM 流程注入；
3. 模型切换后，下一次录音立即使用新模型，录音条和历史中显示的模型名同步更新；
4. 选择“中文”时输出为简体中文；
5. 录音不足 0.5 秒时不发请求，直接得到空结果，不注入幻觉文本；
6. 401、403、413、429、5xx 都有明确的中英文错误提示；
7. API Key 只存在 macOS Keychain 中。

## 3. 非目标

第一版不包含：

- 实时流式识别（Groq 没有公开的音频流式 ASR 接口）；
- `/audio/translations` 语音翻译接口（Type4Me 已有基于 LLM 的翻译模式）；
- 自定义模型名或自定义 Base URL（需要的用户可继续用 OpenAI Provider 或自定义 Provider）；
- FLAC / MP3 本地压缩上传；
- 长音频分片拼接；
- 词级时间戳；
- Groq Batch API / Flex 处理档位；
- 把 Groq 作为 LLM Provider 加入（Groq 是推理托管平台，不是基础模型厂商，按 LLM Provider 收录政策应通过“自定义 OpenAI 兼容”接入）；
- 进入“推荐”分组。

## 4. Provider 定位

### 4.1 名称与分组

- 中英文显示名都为 `Groq`；
- 归入“云端”分组，按字母排序；
- 列表行自动显示“非实时 / Batch”标签（由 capability 决定，无需单独处理）；
- 不进入推荐分组。是否推荐等真实评测后再决定。

### 4.2 与 Grok 的区分

`Groq` 与 xAI 的 `Grok` 名称只差一个字母，按字母排序后会紧挨在一起。区分方式：

1. 使用 Groq 官方品牌图标，与 Grok 的黑白图标在视觉上明显不同；
2. Provider 详情页说明首句写明“Groq 推理平台托管的 OpenAI Whisper 模型”；
3. API Key 占位符使用 `gsk_...`（Grok 是 `xai-...`），用户粘贴时能自然发现选错了。

不在名称中加后缀（如“Groq Whisper”），以保持品牌名准确，也与其他 Provider 的命名方式一致。

### 4.3 适用场景

适合：

- 想要低成本、低延迟的 BYOK 云端听写；
- 中英文及其他多语种输入；
- 已经习惯“松手后出字”的用户。

不适合：

- 需要边说边出字的场景（请用火山、Soniox、Deepgram 等实时 Provider）；
- 热词需求很强的专业场景（Whisper prompt 只是“引导”，不保证命中）；
- 单次超过约 12 分钟的超长录音；
- 无法访问 `api.groq.com` 的网络环境（部分地区需要代理；遇到 403 时提示用户检查网络地区）。

## 5. 核心交互

### 5.1 录音阶段

- 正常采集 16 kHz 单声道 PCM 并缓存；
- 录音条显示通用的“录音中…”占位；
- 不发起任何网络请求。

### 5.2 松开快捷键后

1. 录音短于 0.5 秒：不发请求，直接以空结果结束；
2. 录音超过约 12 分钟：不发请求，提示录音过长；
3. 封装为 WAV，以 multipart 上传到 Groq；
4. 收到结果后过滤静音段，一次性给出最终文本；
5. 进入现有 Direct / LLM 后处理 / 注入流程。

用户感知：`录音中 → 识别中 → 完成`。Groq 不支持增量返回文本，最终结果一次性出现，但通常很快。

### 6.3 语言选项

| 值 | 中文文案 | 英文文案 |
|---|---|---|
| 空 | 自动检测 | Auto-detect |
| `zh` | 中文（简体） | Chinese (Simplified) |
| `en` | 英文 | English |
| `ja` | 日语 | Japanese |
| `ko` | 韩语 | Korean |

说明：

- Groq 只接受 ISO-639-1 两字母代码；Whisper 支持的语种远多于此，这里只列出常用语种，与 Grok Provider 的做法一致；

## 7. 中文简体输出

Whisper 对中文可能输出繁体，或在同一句里繁简混杂。原设计用一段简体中文的 `prompt` 引导输出风格，2026-10-18 的实测（开发设计 G-3、G-4、G-5）推翻了这个方案：

- 语言选“中文（简体）”时，不加引导语也稳定输出简体（80 次识别，繁体字为 0）；
- 语言为“自动检测”时加引导语，Turbo 会把英文句子错误地转成中文，甚至变成幻觉文本；
- 引导语还会诱发“请不吝点赞 订阅 转发…”这类中文幻觉；
- 但“自动检测”且不加引导语时，中英混合句子偶尔会输出繁体。

产品规则：

- **不使用简体引导语**；
- 识别结果被模型判定为中文，并且语言选“中文（简体）”，或语言为“自动检测”且 App 界面为中文时，Type4Me 在本地把繁体转换为简体；
- App 界面为英文时不转换，避免误伤有意输入繁体的用户。

## 8. 热词

Whisper 没有专门的热词参数，但 `prompt` 能引导专有名词的拼写。实测效果明显：不带热词时 “Type4Me” 被识别成 “Tarpe4默”，“Claude Code” 被识别成 “Cloud Code”；带上热词后两个模型都识别正确。

产品规则：

- 将 Type4Me 热词按原顺序拼接进 `prompt`；
- Groq 的 `prompt` 实际上限为 896 个字节（约 290 个汉字或 890 个英文字符），超出的热词按顺序截断，不报错；
- 静音或噪声时，模型可能把整个热词列表当作识别结果输出，Type4Me 会识别并丢弃这类结果；
- 详情页不宣称“支持热词”，以免用户期望与火山 / Soniox 这类真正的热词增强等同。

## 9. 静音幻觉防护

Whisper 在静音、噪声或极短音频上会“编造”文本。实测中出现的有：静音被识别成 “Thank you.”、“you”，键盘噪声被识别成俄语 “Продолжение следует...”（“未完待续”）或无关短句。对语音输入法来说，把这类文本注入到用户的输入框是严重的体验问题。

实测还证明：Groq 返回的幻觉文本置信度很高，**无法从识别结果的置信度中区分**，所以原设计“丢弃被模型判定为无语音的分段”的做法不可行。

产品规则：

1. 录音短于 0.5 秒不发请求（与现有 OpenAI Provider 阈值一致）；
2. 录音中没有可闻的声音（安静环境下按住快捷键不说话）时不发请求；
3. 识别结果整句等于已知的幻觉短语（如 “Thank you.”、“请不吝点赞 订阅 转发 打赏支持明镜与点点栏目”）时丢弃；
4. 识别结果主要由热词列表组成时，视为模型回显，丢弃；
5. 以上情况都按“未识别到内容”处理，不注入任何文本。

已知局限：在嘈杂环境中不说话，仍可能偶尔得到没有固定模式的短句（如“我会认识。”）。发布后会收集这类样本，持续扩充幻觉短语表。

## 10. 限制与错误体验

### 10.1 官方限制

| 项 | 值 |
|---|---|
| 单文件大小 | 免费档 25 MB，开发者档 100 MB |
| 最短计费时长 | 10 秒（不足 10 秒按 10 秒计费） |
| 免费档速率 | 20 次/分钟，2000 次/天，7200 音频秒/小时，28800 音频秒/天 |

16 kHz 单声道 16-bit WAV 约 32 KB/秒，25 MB 约为 13.6 分钟。Type4Me 按免费档保守设定**单次录音上限 12 分钟**，超出时在本地拦截，不发请求。实测 12 分钟（23 MB）上传成功，约 22 秒出结果；14 分钟（27 MB）被服务端以 413 拒绝。

### 10.2 错误提示

下表是每种场景要传达给用户的意思。实测确认 401、404、413、429 的服务端信息都清晰可读（429 带“Please try again in 3s”），因此直接展示 Groq 返回的 `error.message`；429 信息末尾的组织 ID 与升级链接会被截掉。

| 场景 | 中文提示 | 英文提示 |
|---|---|---|
| API Key 为空 | Groq 非实时识别配置无效 | Invalid Groq batch recognition configuration |
| 401 | Groq API Key 无效或已被撤销 | The Groq API key is invalid or revoked |
| 403 | 当前 API Key 或网络地区无权访问 Groq | This API key or network region cannot access Groq |
| 403（网络防护拦截） | 请求被 Groq 网络防护拦截，请检查代理或网络环境 | The request was blocked by Groq's network protection. Check your proxy or network. |
| 413 | 录音超过 Groq 单次上传大小限制，请缩短后重试 | The recording exceeds Groq's upload size limit. Record a shorter segment. |
| 429 | Groq 请求过于频繁或已达额度上限，请稍后再试（附带服务端返回的等待时间） | Groq rate limit reached. Try again later (includes the server's retry hint). |
| 超过 12 分钟 | 录音超过 Groq 的 12 分钟上限，请缩短后重试 | The recording exceeds Groq's 12-minute limit. Record a shorter segment. |
| 5xx | 优先展示服务端信息，否则显示 HTTP 状态码 | Same |
| 网络超时 | 沿用现有超时提示 | Same |

注意：现有批量 Provider 的“录音过长”提示是“请切换为实时流式”，Groq 没有实时模式，必须使用“请缩短后重试”的文案。

## 11. 测试连接

复用现有批量 Provider 的真实校验方式：向 Groq 提交 1 秒静音，HTTP 200 即视为成功。

- 能真实校验 API Key、模型可用性和网络连通性；
- 每次测试按最短计费 10 秒计费，Turbo 约 $0.0001，Large v3 约 $0.0003，可以忽略；
- 测试结果只看状态码，不展示静音的识别文本。

## 12. 隐私与安全

- API Key 只存 Keychain；`credentials.json` 只存模型和语言；
- 音频只在用户选用 Groq 时发送到 `api.groq.com`；
- 日志不记录 API Key、Authorization 头、音频内容或 prompt 全文（prompt 含用户热词）；
- 错误日志只记录状态码和有长度上限的服务端错误信息；
- 遵循现有“绕过代理”设置。

## 13. 可观测性

沿用现有批量 ASR 日志：PCM 字节数、请求耗时、HTTP 状态码、结果字符数、被过滤的无语音分段数量。录音条与历史记录显示 `Groq · <模型 ID>`。

## 14. 验收场景

1. **基础**：配置有效 Key，默认 Turbo + 自动检测，录一段中文，松开后简体文本正确注入；
2. **模型切换**：切到 Large v3，录音条和历史显示 `Groq · whisper-large-v3`；
3. **英文**：语言选 English，输入英文，标点和大小写正常；
4. **中英混合**：自动检测下说中英混合句子，可正常完成；
5. **简体**：语言选“中文（简体）”，连续多次输入，不出现繁体；
6. **热词**：添加若干英文专有名词热词，确认拼写改善且结果不回显热词列表；
7. **静音**：分别在安静环境和有键盘声的环境中，按住快捷键不说话 2 秒后松开，不注入任何文本（安静环境必须通过；嘈杂环境记录是否出现幻觉文本，用于扩充幻觉短语表）；
8. **极短**：快速点按快捷键（<0.5 秒），不发请求；
9. **错误 Key**：测试连接和实际识别都显示 401 提示，不出现假成功；
10. **速率限制**：短时间内连续触发超过 20 次，出现 429 提示；
11. **处理模式**：Direct、快速、Intelli Sense、翻译、自定义 Prompt 模式都正常工作；
12. **语言切换**：把 App 语言在中英文之间切换，Provider 列表、详情页说明、字段标签、错误提示均即时切换；
13. **菜单栏**：配置完成后，菜单栏 ASR 快速切换中出现 Groq，并带“非实时”标识。

## 15. 发布策略

作为普通云端 Provider 随下个版本发布，在 CHANGELOG 和 README 的 Provider 列表中注明“非实时”。发布后观察：

- 松手到出字的端到端延迟；
- 429 出现频率（免费档 20 次/分钟对高频用户可能偏紧）；
- 静音幻觉的漏网情况；
- 中文用户对繁简输出的反馈；
- 用户是否把 Groq 与 Grok 混淆。

## 16. 待实测事项

以下产品承诺依赖真实接口的表现。方法、判定和完整结果记录在开发设计第 2.1 节，编号一致。2026-10-18 已完成全部 A、B 级实测：

| 编号 | 涉及的产品承诺 | 实测结论 | 产品调整 |
|---|---|---|---|
| G-1、G-5 | 第 9 节：静音和噪声不注入幻觉文本，轻声说话不被误删 | 置信度过滤无效；轻声说话识别正常 | 已改为本地静音门限 + 幻觉短语过滤（第 9 节） |
| G-2 | 第 8 节：热词放进 prompt 不会导致请求失败 | 上限为 896 字节，超出返回 400 | 已按字节截断（第 8 节） |
| G-3 | 第 7 节：选“中文（简体）”时输出简体 | 不加引导语也稳定输出简体 | 取消引导语（第 7 节） |
| G-4 | 第 7 节：自动检测时不影响英文 | 加引导语会把英文转成中文；不加则偶有繁体 | 取消引导语，改为本地繁转简（第 7 节） |
| G-6 | 第 8 节：结果不回显热词列表 | Large v3 静音时会回显整个热词列表；热词改善拼写效果明显 | 增加回显识别（第 8、9 节） |
| G-7 | 第 10.1 节：单次录音上限 12 分钟 | 12 分钟成功，14 分钟被 413 拒绝 | 无 |
| G-8 | 第 10.2 节：错误提示可读，429 带等待时间 | 全部可读 | 直接展示服务端信息（第 10.2 节） |
| G-9 | 第 11 节：测试连接真实可用 | 1 秒静音返回 200 | 无 |

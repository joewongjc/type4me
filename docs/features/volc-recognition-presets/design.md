# 火山引擎识别方案：准确 / 快速 / 自定义

火山引擎设置页的「识别高级设置」让用户在断句速度和标点质量之间取舍。默认是「准确」，与 v2.14.0 的断句行为相同。

## 背景

火山 bigmodel_async 按静音把录音切成句子，每句单独识别、单独加标点。断句时长决定两件事：

- **松手后多快出字**：断句越早，松手时剩下要识别的尾句越短。
- **标点是否被停顿打断**：停顿超过断句时长时，标点模型只能看到半句话，“如果你。不能读到”这类句号就来自这里。

2026-10-24 用 43 条用例（37 条真实录音 + 6 条合成语音）对比了两套参数：快速方案松手到出字的中位数为 520 ms，准确方案为 687 ms；快速方案平均每条多切出约 1 句，停顿处的逗号更容易变成句号。润色、感知模式下大模型会修正这些差异，两套方案的输出基本一致。

## 方案定义

| 项目 | 准确（默认） | 快速 |
|---|---|---|
| 逐句精修（`enable_nonstream`） | 开 | 开 |
| 断句（`end_window_size`） | 3000 ms | 不发送，服务端默认约 800 ms |
| 开口保护（`force_to_speech_time`） | 0 | 不发送 |
| `vad_segment_duration` | 不发送 | 6000（按文档在此组合下不生效，保留以与评测一致） |
| `context_history_length` | 20 | 50 |
| 中文句子之间不加空格 | 开 | 开 |
| 松手后最长等待 | 2 s，超时后再等最多 5 s | 3 s，超时直接输入已识别文字 |
| 短录音等待 / 音频发送间隔 | 1 s / 200 ms | 1 s / 200 ms |

「中文句子之间不加空格」是缺陷修复，两个方案都开启：服务端 `result.text` 在每两句之间插入 ASCII 空格，客户端改为按 CJK 规则拼接各句，并去掉句子边界上残留的空白。

## 自定义

- 第一次切到「自定义」时，复制当时生效的方案作为起点；之后切回「准确」或「快速」，自定义的值仍保留。
- 「重置」可把自定义改成与「准确」或「快速」一致，需确认。
- 「请求参数」以火山的原始字段名作标题（`enable_nonstream`、`end_window_size` 等），说明只写字段的实际作用、文档默认值与已实测的现象，不做评价。开关表示是否发送该字段，发送时才显示取值滑块；`force_to_speech_time` 只能在发送 `end_window_size` 时开启。
- `context_history_length` 在文档中没有找到说明，界面如实注明，取值 0 表示不发送。
- 「客户端处理」是 Type4Me 自己的处理，没有对应字段，用中性的描述命名：分句拼接、松手后最长等待、超时处理、短录音首字等待、音频分包时长。
- 时长一律以毫秒显示，与字段单位一致。

## 存储

- `tf_volcRecognitionProfile`：`{preset, custom}`。
- 本地测试期的 `tf_volcTuning` 会在首次读取时迁移：与某个方案完全一致就选该方案，否则作为自定义保存，随后删除旧键。

## 代码

- `Type4Me/Services/VolcTuningSettings.swift`：参数、方案、存储与 `CJKAwareJoiner`。
- `Type4Me/UI/Settings/VolcRecognitionSettingsSection.swift`：设置界面。
- 请求字段在 `VolcProtocol.buildClientRequest` 合并；停止流程的等待在 `RecognitionSession.stopRecording`；音频分包在 `AudioCaptureEngine.start`。
